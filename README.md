# CaptureErrorsSession
<small>_(This README was generated by GitHub Copilot)_</small>

A SQL Server stored procedure that captures SQL errors raised during a session using Extended Events, scoped to the calling session and application.

## Overview

`Tools.CaptureErrorsSession` creates and manages a named Extended Events session that captures `error_reported` events with severity >= 11, filtered to the current `@@SPID` and application name (`APP_NAME()`). Results are returned as JSON.

The procedure works on both **Azure SQL Database / Azure SQL Database on Fabric** (database-scoped sessions) and **SQL Server on-premises / SQL Managed Instance** (server-scoped sessions), detected automatically via `SERVERPROPERTY('EngineEdition')`.

## Why This Exists

In real-world failures, `ERROR_MESSAGE()` can be misleading because it often returns only the last error raised in a chain.

Common cases this procedure addresses:

- A DDL operation fails for a root cause (for example, a default constraint exists on a column), but the surfaced message can hide that root cause.
- `OPENQUERY` timeout scenarios can emit multiple errors (for example, a timeout plus a secondary/dummy "cannot run query" error). The secondary error is often what `ERROR_MESSAGE()` returns, masking the original timeout.

The primary goal of `Tools.CaptureErrorsSession` is reliable error capture for SQL Agent jobs.

Why the `APP_NAME()` filter matters for jobs:

- SQL Agent application name includes job and step context, which helps attribute errors to the correct execution.
- If an event session is still alive and a SPID gets reused later, filtering by both SPID and app name reduces cross-contamination from unrelated work.

## Installation

Run `CaptureErrorsSession.sql` in the target database. The procedure is created in (or altered in) the `Tools` schema.

## Usage

```sql
DECLARE @result nvarchar(MAX);
DECLARE @SessionEvent sysname = 'MyErrorSession';

-- 1. Create the Extended Events session
EXEC Tools.CaptureErrorsSession
    @SessionEvent = @SessionEvent,
    @Action       = 'CREATE',
    @result       = @result OUTPUT;

-- 2. Start capturing
EXEC Tools.CaptureErrorsSession
    @SessionEvent = @SessionEvent,
    @Action       = 'START',
    @result       = @result OUTPUT;

-- ... run your code here ...

-- 3. Retrieve captured errors as JSON
EXEC Tools.CaptureErrorsSession
    @SessionEvent = @SessionEvent,
    @Action       = 'GET',
    @result       = @result OUTPUT;
PRINT @result;

-- 4. Stop and clean up
EXEC Tools.CaptureErrorsSession @SessionEvent = @SessionEvent, @Action = 'STOP',  @result = @result OUTPUT;
EXEC Tools.CaptureErrorsSession @SessionEvent = @SessionEvent, @Action = 'DROP',  @result = @result OUTPUT;
```

## Parameters

| Parameter      | Type            | Description                                                  |
|----------------|-----------------|--------------------------------------------------------------|
| `@SessionEvent`| `sysname`       | Name for the Extended Events session. Must start with a letter and contain only alphanumeric characters and underscores. |
| `@Action`      | `varchar(10)`   | One of: `CREATE`, `START`, `STOP`, `DROP`, `GET`.           |
| `@result`      | `nvarchar(MAX)` | OUTPUT parameter. Returns a JSON status object or, for `GET`, a JSON array of captured errors. |

## Actions

| Action   | Description                                                                                     |
|----------|-------------------------------------------------------------------------------------------------|
| `CREATE` | Creates the Extended Events session (drops and recreates if it already exists). Scoped to the current `@@SPID` and `APP_NAME()`. See [Application Name validation](#application-name-validation) below. |
| `START`  | Starts the session to begin capturing errors.                                                   |
| `STOP`   | Stops the session.                                                                              |
| `DROP`   | Drops the session entirely.                                                                     |
| `GET`    | Reads captured events from the ring buffer and returns them as a JSON array.                    |

## Application Name Validation

During `CREATE`, the procedure reads `APP_NAME()` and embeds it directly into a dynamic SQL string literal to use as an event filter. Because this value comes from the client connection — outside the procedure's control — it is treated as user input and validated before use:

- **NULL or empty** — rejected; a blank app name would create a useless filter.
- **`CHAR(0)` (null byte)** — rejected; a null byte can silently truncate strings in certain SQL Server contexts, which could bypass the sanitization step below.
- **Single-quote escaping** — remaining single quotes are doubled (`'` → `''`) to prevent SQL injection when the value is embedded in the dynamic statement.

## GET Output Format

```json
[
  {
    "error_number": 4924,
    "severity": 16,
    "message_text": "ALTER TABLE failed because column 'x' does not exist in table 'TestError'."
  }
]
```

Returns `[]` if no errors were captured.
